Why do we need CloudFormation?
Suppose you want to deploy a web application with:
- An Amazon VPC
- Public and private subnets
- EC2 instances
- An Application Load Balancer
- An RDS database
You could create each resource manually through the AWS Console. But this takes time and can lead to configuration mistakes.
With CloudFormation, you describe the required infrastructure in a template. CloudFormation provisions the resources for you.
Example: You can reuse the same template to create development, testing, and production environments with consistent infrastructure.
2. How CloudFormation works
1. Write a template
Usually YAML or JSON

2. Create a CloudFormation stack
CloudFormation interprets the template

3. AWS resources are provisioned
VPC, EC2, S3, RDS, and other supported resources


3. Important CloudFormation terminology
Term	Meaning
Template	A YAML or JSON file describing the infrastructure you want.
Stack	A collection of AWS resources managed together through a template.
Change set	A preview of proposed changes to a stack before you execute them.
Stack drift	A difference between the actual resource configuration and the configuration CloudFormation expects from the template.
Rollback	Reverts a failed stack operation where rollback is supported and enabled.
Nested stack	A stack managed as part of another stack, useful for reusable infrastructure components.
Template sections to recognize
A CloudFormation template can include:
- Parameters — values supplied when creating or updating a stack.
- Resources — AWS resources to create; this is the main required section.
- Outputs — values to display or export, such as a resource ID or URL.
- Mappings — static lookup tables.
- Conditions — rules that determine whether resources or properties are included.
- Metadata — additional information about the template or resources.
Resources is the key section for the exam.
4. Example CloudFormation template
This simple YAML template creates an S3 bucket.
AWSTemplateFormatVersion: '2010-09-09'
Description: Simple S3 bucket example

Resources:
  MyBucket:
    Type: AWS::S3::Bucket


What happens when you deploy it?
1. CloudFormation reads the template.
2. It creates a stack.
3. The stack provisions the S3 bucket.
4. You can manage the bucket through subsequent stack updates and deletion behavior.
The bucket name is generated by AWS because the template does not specify one. Deleting a stack does not always mean every resource can be deleted automatically; for example, a non-empty S3 bucket can prevent successful deletion.
5. Benefits of CloudFormation
- Automation: Provision infrastructure without creating each resource manually.
- Consistency: Reuse templates for repeatable environments.
- Version control: Store templates in Git and review changes.
- Dependency management: CloudFormation determines resource creation order based on dependencies.
- Change sets: Inspect proposed infrastructure changes before execution.
- Drift detection: Identify supported resource configuration changes made outside CloudFormation.
- Rollback: Recover from certain failed operations.
6. CloudFormation vs Terraform
Since you have worked with Terraform, this distinction is particularly useful.
Feature	AWS CloudFormation	Terraform
Provider	AWS-native service	HashiCorp tool supporting multiple providers
Configuration	YAML or JSON templates	HCL, primarily
State management	AWS manages stack state	Uses Terraform state
AWS integration	Native AWS resource management	AWS provider
Multi-cloud support	Primarily AWS infrastructure	Multiple cloud providers and platforms
Main use	Define and manage AWS infrastructure	Define and manage infrastructure across providers
Exam point: Both support Infrastructure as Code. CloudFormation is AWS-native, while Terraform is a third-party, multi-provider IaC tool.
7. CloudFormation vs AWS Service Catalog
- CloudFormation: Defines and provisions infrastructure from templates.
- AWS Service Catalog: Lets organizations create and distribute approved portfolios of IT products, often backed by CloudFormation templates.
For example, an IT administrator can offer developers an approved database configuration through Service Catalog rather than allowing everyone to create arbitrary infrastructure.
