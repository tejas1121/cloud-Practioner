1. IAM Password Policy
An IAM password policy defines requirements for passwords used by IAM users to sign in to the AWS Management Console.
It helps an organization enforce stronger passwords and reduce the risk of compromised accounts.
What can a password policy control?
- Minimum password length: Require a minimum number of characters.
- Character requirements: Require uppercase letters, lowercase letters, numbers, and non-alphanumeric characters.
- Password expiration: Require users to change passwords periodically, if configured.
- Password reuse prevention: Prevent users from reusing previous passwords, within the supported policy limits.
- Allow or prevent users from changing their own passwords: Control whether IAM users can manage their passwords themselves.
These settings are configurable; AWS does not require every account to use every restriction.
Example
Suppose your NovaSRE team has five developers with IAM users.
Your organization configures a password policy requiring:
- At least 12 characters.
- Uppercase and lowercase letters.
- Numbers and special characters.
- No reuse of the last five passwords.
This policy helps establish consistent password requirements for IAM users.
Exam takeaway

An IAM password policy controls password requirements. It does not provide a second authentication factor—that is the role of MFA.

Important exam distinction
An IAM account password policy applies to IAM users signing in to the AWS console. The AWS account root user has separate credential-management considerations; don't assume every IAM user password-policy setting applies identically to root credentials.
2. What is MFA?
MFA stands for Multi-Factor Authentication.
It adds an additional authentication factor beyond your password, helping protect an account even if the password is stolen.
The common authentication factors are:

1. Something you know
Example: A password or PIN.



2. Something you have
Example: An authenticator device, security key, or phone running an authenticator app.



3. Something you are
Example: A fingerprint or facial biometric used by a supported authentication system.



A password plus a code from an authenticator app combines two different factors: something you know and something you have.
Exam trap: Using two passwords is not MFA because both are the same type of factor.
3. Types of MFA in AWS









1. Virtual MFA device
Uses an authenticator application to generate time-based one-time passwords (TOTP).
Examples include supported authenticator apps.
Exam clue: A code generated by an authenticator app.












2. FIDO security key
A physical security key that uses public-key cryptography for phishing-resistant authentication.
Exam clue: Hardware key and phishing-resistant sign-in.












3. Hardware TOTP token
A dedicated physical device generates time-based one-time passwords.
Exam clue: A physical token that displays a changing authentication code.












4. Supported device-based MFA methods
AWS supports additional MFA options for eligible authentication flows, including supported device-based methods.
Exam clue: Know that AWS MFA is not limited to physical OTP tokens.



4. Protecting the AWS root user
The root user is the identity created when an AWS account is created. It has extensive privileges and should be protected carefully.
Follow these security best practices:
1. Enable MFA for the root user.
2. Avoid using root credentials for everyday administration.
3. Do not share root credentials or access keys.
4. Use IAM roles and appropriately permissioned identities for routine work.
5. Keep root-user recovery methods secure.
The root user is different from an IAM administrator. An IAM identity with AdministratorAccess does not automatically have every capability reserved for the root user.
Exam scenario: A question asks for the most important additional authentication safeguard for the AWS root user. The expected answer is usually to enable MFA on the root user.
5. Password policy vs MFA
Feature	Password policy	MFA
Main purpose	Enforce password requirements	Add another authentication factor
Example	Minimum password length	Password plus authenticator code
Helps against	Weak or poorly managed passwords	Password-only account compromise
Required for every IAM user by default?	No universal account-specific rule requiring every optional setting	MFA should be enabled according to security best practices and organizational requirements
Memory trick: Password policy strengthens the password; MFA strengthens the sign-in process.
